`cadkit-capi` exposes cadkit through a small C ABI (`cadkit.h`) and a header-only C++17
wrapper (`cadkit.hpp`). The header is the contract: functions are only added in minor
versions, and existing signatures, enum values and struct layouts change only with a major
version.

## Get the library

Each [GitHub release](https://github.com/TNYCL/cadkit/releases/latest) has a
`cadkit-capi-<target>` archive for `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu`
(both built against glibc 2.28), `aarch64-apple-darwin`, `x86_64-apple-darwin` and
`x86_64-pc-windows-msvc`. It contains `include/` (`cadkit.h`, `cadkit.hpp`), `lib/` with the
shared and the static library, the license files and the API reference. Checksums are listed in
`SHA256SUMS` on the release.

Prefer the shared library: the static one also needs the platform libraries Rust's standard
library uses. With MSVC, link `cadkit_capi.dll.lib` and ship `cadkit_capi.dll` next to the
executable.

The conventions in brief: every fallible function returns a `cadkit_status` and writes its
result through an out-pointer; `cadkit_last_error_message()` explains the last failure on the
calling thread; strings are UTF-8. Release documents with `cadkit_document_free`, strings with
`cadkit_string_free` and byte buffers with `cadkit_bytes_free`. No Rust panic crosses the
boundary. The full rules are in the [C and C++ API reference](/docs/reference/c-api/).

Building from a checkout instead, `cargo build -p cadkit-capi --release` produces the
libraries in `target/release/`, and `cmake --install` of `crates/cadkit-capi` installs a CMake
package (`find_package(cadkit CONFIG REQUIRED)`, target `cadkit::cadkit`) and a pkg-config file.
See [Install for CMake and pkg-config consumers](/docs/reference/c-api/#install-for-cmake-and-pkg-config-consumers).
